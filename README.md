# Wahm Pay — بوابة دفع ذاتية الاستضافة

نظام تحقق تلقائي من الحوالات البنكية: تنشئ فاتورة بمبلغ فريد بالهللات، يحوّل العميل المبلغ إلى آيبانك، واختصار الآيفون يرسل رسالة البنك إلى الخادم، ثم يقرأها Gemini ويؤكد الفاتورة فوراً مع إشعار تيليجرام.

يعمل بـ **Python / Flask** وقاعدة **SQLite** مدمجة، ومهيأ للرفع على [Render.com](https://render.com) بدون إعداد قاعدة بيانات خارجية.

## كيف يعمل النظام؟

1. من لوحة التحكم (أو عبر API) تنشئ فاتورة: اسم المنتج + السعر الأساسي + رابط توجيه اختياري بعد الدفع.
2. النظام يولّد توكن فريد مثل `PAY-8942X` ويضيف هللات عشوائية فريدة للمبلغ (مثال: `50.00` تصبح `50.14`) حتى لا تتداخل حوالتان في نفس اللحظة.
3. تحصل على **رابط دفع** ترسله للعميل أو تضعه في متجرك / بوت تيليجرام.
4. العميل يرى المبلغ الدقيق والآيبان وعدّاداً تنازلياً، ويحوّل المبلغ **بالضبط**.
5. عند وصول رسالة البنك إلى جوالك، اختصار iOS يرسل نص الرسالة إلى `/webhook/sms`.
6. Gemini يستخرج المبلغ واسم المرسل والبنك والمرجع. إذا طابق المبلغ فاتورة معلّقة تتحول إلى **مدفوعة**، وتتحدث صفحة العميل تلقائياً خلال 3 ثوانٍ، ويصلك إشعار تيليجرام.

## متغيرات البيئة

انسخ `.env.example` إلى `.env` على جهازك المحلي، أو أضفها من لوحة Render → Environment.

| المتغير | مطلوب؟ | الوصف |
|---|---|---|
| `ADMIN_PASSWORD` | نعم | كلمة مرور لوحة التحكم `/admin` |
| `SECRET_KEY` | نعم | مفتاح حماية `/webhook/sms` و `/api/create-invoice`. يُرسل في الترويسة `X-Secret-Key` |
| `FLASK_SECRET_KEY` | مستحسن جداً | مفتاح توقيع كوكيز الجلسة. إذا لم يُضبط يُولَّد عشوائياً عند كل إعادة تشغيل وتُفقد جلسات الدخول |
| `GEMINI_API_KEY` | نعم (للتحقق الحي) | مفتاح Google Gemini من [Google AI Studio](https://aistudio.google.com/apikey) |
| `TELEGRAM_BOT_TOKEN` | مستحسن | توكن بوت الإشعارات |
| `TELEGRAM_CHAT_ID` | مستحسن | معرّف المحادثة التي يستقبل فيها التاجر الإشعارات |
| `MERCHANT_IBAN` | نعم للعملاء | رقم الآيبان الذي يظهر في صفحة الدفع |
| `MERCHANT_NAME` | مستحسن | اسم صاحب الحساب (الافتراضي: التاجر) |
| `BASE_URL` | مستحسن | الرابط العام بدون شرطة مائلة أخيرة، مثال: `https://wahm-pay.onrender.com` |
| `INVOICE_VALIDITY_MINUTES` | لا | مدة صلاحية الفاتورة بالدقائق (الافتراضي `15`) |
| `DATABASE_PATH` | لا | مسار ملف SQLite. على Render استخدم قرصاً ثابتاً مثل `/var/data/payments.db` |
| `PORT` | تلقائي | Render يضبطه بنفسه |

لا تضع أي سر حقيقي داخل الملفات أو في Git.

### الحصول على مفتاح Gemini

1. ادخل إلى [Google AI Studio](https://aistudio.google.com/apikey).
2. أنشئ مفتاح API وانسخه إلى `GEMINI_API_KEY`.
3. النموذج المستخدم حالياً ثابت في أعلى `app.py` باسم `GEMINI_MODEL = "gemini-2.0-flash"`. غيّره من هناك بسهولة إذا ظهر نموذج أحدث.

### الحصول على توكن بوت تيليجرام و Chat ID

1. افتح تيليجرام وابحث عن [@BotFather](https://t.me/BotFather).
2. أرسل `/newbot` واتبع التعليمات، ثم انسخ التوكن إلى `TELEGRAM_BOT_TOKEN`.
3. ابدأ محادثة مع البوت الجديد (اضغط Start).
4. لمعرفة `TELEGRAM_CHAT_ID`:
   - أرسل للبوت أي رسالة.
   - افتح في المتصفح: `https://api.telegram.org/bot<TOKEN>/getUpdates`
   - ابحث عن `"chat":{"id": 123456789}` وضع هذا الرقم في `TELEGRAM_CHAT_ID`.
   - إذا كانت المجموعة، قد يكون المعرّف سالباً (مثلاً `-100123…`) وهذا طبيعي.

## خطوات الرفع على Render.com

> ملاحظة مهمة عن SQLite: في الخطة المجانية ملفات القرص تُمسح عند إعادة التشغيل. لتخزين الفواتير بشكل دائم أضف **Persistent Disk** في Render (Mount path: `/var/data`) واضبط `DATABASE_PATH=/var/data/payments.db`. ملف `render.yaml` يتوقع هذا المسار.

1. ارفع المشروع إلى مستودع Git (خاص يفضَّل لأنه كود دفع).
2. ادخل إلى [Render Dashboard](https://dashboard.render.com) وسجّل الدخول.
3. **New +** → **Web Service** → اربط المستودع.
4. الإعدادات:
   - **Runtime:** Python 3
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 8 --timeout 120`
   - **Instance:** Starter أو أعلى (worker واحد مناسب لـ SQLite).
5. من تبويب **Environment** أضف كل المتغيرات في الجدول أعلاه. لا تنسَ:
   - `ADMIN_PASSWORD`
   - `SECRET_KEY` (سلسلة طويلة عشوائية)
   - `FLASK_SECRET_KEY` (سلسلة طويلة عشوائية مختلفة)
   - `GEMINI_API_KEY`
   - `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID`
   - `MERCHANT_IBAN` و `MERCHANT_NAME`
   - `BASE_URL` = رابط خدمة Render بعد إنشائها (يمكنك حفظه بعد أول نشر ثم تحديثه)
   - `INVOICE_VALIDITY_MINUTES=15`
   - `DATABASE_PATH=/var/data/payments.db` إذا أضفت قرصاً ثابتاً
6. (اختياري) **Disks** → أضف قرصاً بحجم صغير (1 GB يكفي) ومسار التثبيت `/var/data`.
7. اضغط **Deploy**. بعد نجاح البناء افتح `/health` يجب أن يرجع `{"ok": true, ...}`.
8. افتح `/login` وادخل بكلمة `ADMIN_PASSWORD` ثم أنشئ فاتورة تجريبية.

يمكنك أيضاً استخدام `render.yaml` عبر **New +** → **Blueprint**. بعد الربط ستُطلب منك القيم السرية (`sync: false`).

## واجهة API

جميع النقاط المحمية تتطلب المفتاح في أحد الأشكال التالية:

- ترويسة: `X-Secret-Key: YOUR_SECRET_KEY`  ← المفضّلة
- أو: `Authorization: Bearer YOUR_SECRET_KEY`
- أو حقل `secret` داخل جسم JSON

### إنشاء فاتورة

`POST /api/create-invoice`

```json
{
  "product_name": "اشتراك شهري",
  "price": 50,
  "redirect_url": "https://example.com/thank-you"
}
```

الرد:

```json
{
  "ok": true,
  "token": "PAY-8942X",
  "payment_link": "https://your-app.onrender.com/pay/PAY-8942X",
  "amount": "50.14",
  "base_price": "50.00",
  "status": "Pending",
  "expires_at": "2026-11-15T00:30:00Z",
  "product_name": "اشتراك شهري"
}
```

مثال `curl`:

```bash
curl -X POST https://YOUR-APP.onrender.com/api/create-invoice \
  -H "Content-Type: application/json" \
  -H "X-Secret-Key: YOUR_SECRET_KEY" \
  -d '{"product_name":"اشتراك شهري","price":50,"redirect_url":"https://example.com/thanks"}'
```

### حالة فاتورة (عامة حسب التوكن)

`GET /api/status/PAY-8942X`

تستخدمها صفحة الدفع للفحص كل 3 ثوانٍ، ولا تحتاج مفتاحاً سرياً لأن التوكن نفسه سري بما يكفي.

### Webhook رسائل البنك

`POST /webhook/sms`

```json
{ "text": "نص رسالة البنك كاملاً هنا" }
```

يُقبل أيضاً الحقول: `sms`, `message`, `body`.

## إعداد اختصار الآيفون (iOS Shortcuts) بالتفصيل

الهدف: كلما وصلت رسالة من البنك، يُرسل نصها تلقائياً إلى Wahm Pay.

### أ) إنشاء الاختصار نفسه

1. افتح تطبيق **الاختصارات** على الآيفون.
2. اضغط **+** لإنشاء اختصار جديد، وسمّه مثلاً: `إرسال رسالة البنك لـ Wahm Pay`.
3. أضف الإجراء **إدخال نص** (Text) مؤقتاً للتجربة، أو اترك الاختصار يستقبل نصاً من الاختصار السابق / الأتمتة (موضح في الخطوة ب).
   - الأفضل: في إعدادات الاختصار (زر ⓘ أو السهم) فعّل **إظهار في ورقة المشاركة** إن أحببت تشغيله يدوياً على رسالة.
4. أضف الإجراء **الحصول على محتويات الرابط** (Get Contents of URL):
   - **URL:** `https://YOUR-APP.onrender.com/webhook/sms`
   - **Method:** `POST`
   - **Headers:** أضف ترويستين:
     - `Content-Type` = `application/json`
     - `X-Secret-Key` = القيمة نفسها الموجودة في متغير `SECRET_KEY` على Render
   - **Request Body:** JSON
   - أضف حقلاً واحداً:
     - المفتاح: `text`
     - القيمة: **نص الرسالة** (Shortcut Input / Message Body / محتوى الرسالة — حسب مصدر التشغيل)
5. (اختياري) أضف إجراء **إظهار تنبيه** يعرض الرد حتى تتأكد أن الخادم ردّ بـ `"result": "paid"` أو `"unmatched"`.
6. احفظ الاختصار.

جسم الطلب النهائي يجب أن يكون بهذا الشكل تماماً:

```json
{
  "text": "نص رسالة البنك كما وصلت بالكامل"
}
```

والترويسة الإلزامية:

```
X-Secret-Key: ضع_هنا_نفس_SECRET_KEY
Content-Type: application/json
```

### ب) الأتمتة عند استلام رسالة البنك

1. في تطبيق الاختصارات افتح تبويب **الأتمتة** (Automation).
2. **أتمتة جديدة** → **رسالة** (Message) → **عند استلام الرسالة**.
3. حدّد المرسل: رقم البنك أو اسم جهة الاتصال المحفوظة للبنك (مثال: الراجحي، الأهلي، STC Pay…).
   - إذا كان البنك يرسل من أكثر من رقم، أنشئ أتمتة لكل رقم أو اتركها لكل الرسائل ثم صفِّ داخل الاختصار (أقل دقة).
4. اختر **تشغيل الاختصار** `إرسال رسالة البنك لـ Wahm Pay`.
5. مرّر **نص الرسالة** (Message Body / محتوى الرسالة) كمدخل للاختصار، ليصبح هو قيمة الحقل `text`.
6. في iOS الحديث يُفضَّل تعطيل «اسأل قبل التشغيل» حتى يتم الإرسال فوراً بدون تدخل (قد يطلب النظام موافقة أولى).
7. احفظ الأتمتة.

### ج) تجربة يدوية قبل الاعتماد

1. أنشئ فاتورة من لوحة التحكم واتركها معلّقة.
2. شغّل الاختصار يدوياً والصق نص رسالة بنك تجريبية (أو رسالة حقيقية قديمة) تحتوي **نفس المبلغ بالهللات** الظاهر في الفاتورة.
3. راقب:
   - رد الاختصار (يجب أن يحتوي `"result": "paid"` إذا تطابق المبلغ).
   - صفحة الدفع تتحدث إلى «تم الدفع بنجاح».
   - إشعار تيليجرام يصل إليك.
   - سجل الـ Webhook في لوحة التحكم.

إذا حصلت على `401` فالمفتاح السري غير مطابق. إذا حصلت على `502` فتحقق من `GEMINI_API_KEY`. إذا كانت النتيجة `unmatched` فالمبلغ في الرسالة لا يطابق أي فاتورة معلّقة بالهللات تماماً.

## حالات الرد في الـ Webhook

| `result` | المعنى |
|---|---|
| `paid` | تمت مطابقة المبلغ مع فاتورة معلّقة وتحويلها إلى مدفوعة |
| `already_paid` | يوجد فاتورة مدفوعة مسبقاً بنفس المبلغ |
| `expired` | المبلغ يطابق فاتورة انتهت صلاحيتها (تُسجَّل كحوالة غير مطابقة) |
| `unmatched` | لا توجد فاتورة معلّقة بهذا المبلغ بالضبط |
| `ignored` | الرسالة ليست إيداعاً صالحاً (سحب، OTP، إعلان، أو تعذر استخراج المبلغ) |

الخادم لا ينهار على مدخلات سيئة؛ يرجع JSON واضح ويسجّل الحدث في لوحة التحكم.

## ملاحظات أمنية وتشغيلية

- لا تشارك `SECRET_KEY` أو كلمة الأدمن أو مفاتيح Gemini/Telegram.
- روابط الدفع تحتوي توكن عشوائي؛ لا تجعل التوكنات القديمة علنية إن لم تعد بحاجة إليها.
- المطابقة تتم على المبلغ **بالهللة** تماماً. لذلك يجب أن يحوّل العميل الرقم الظاهر كما هو.
- صفحة الدفع تفحص الحالة كل 3 ثوانٍ، وعند النجاح تظهر «✅ تم الدفع بنجاح» وتحوّل تلقائياً إلى `redirect_url` إن وُجد.
- نموذج Gemini ثابت في `GEMINI_MODEL` أعلى `app.py` لسهولة التغيير.
- استخدم عاملاً واحداً (`--workers 1`) مع SQLite كما في الـ Procfile.
